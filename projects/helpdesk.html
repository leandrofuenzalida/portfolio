Full Stack Project

HelpDesk

Aplicación Full Stack para gestionar tickets de soporte mediante una API REST común a una interfaz Web, un cliente CLI y herramientas de prueba como Postman.

Contexto

Problema

HelpDesk busca centralizar solicitudes de soporte en tickets que puedan crearse, consultarse, editarse, filtrarse y cerrarse. Cada ticket puede registrar prioridad, urgencia, progreso, fecha de vencimiento y un archivo adjunto.

Implementación

Solución

La aplicación expone una API REST en Express. Los controllers traducen HTTP hacia services reutilizables; Sequelize representa el modelo relacional y PostgreSQL mantiene la persistencia.

La interfaz Web y el CLI consumen esa misma API, evitando duplicar las reglas de negocio en clientes diferentes.

Funcionalidades

Capacidades principales

Autenticación

Registro, login, password hashing con bcrypt y protección de endpoints mediante JWT y express-jwt.

CRUD de tickets

Creación, lectura, actualización y eliminación con filtros por estado, prioridad, urgencia y progreso mínimo.

Archivos adjuntos

Upload multipart, validación de archivo, generación de nombre seguro y asociación del path al ticket.

Múltiples clientes

Web y CLI reutilizan el mismo contrato HTTP y las mismas capacidades del backend.

Contrato HTTP

API REST

Método Endpoint Responsabilidad
POST /api/v1/auth/login Autenticar usuario y emitir JWT.
GET /api/v1/tickets Listar tickets y aplicar filtros.
POST /api/v1/tickets Crear un ticket autenticado.
PUT /api/v1/tickets/:id Actualizar un ticket.
DELETE /api/v1/tickets/:id Eliminar un ticket.

Ejemplo de filtro: /api/v1/tickets?status=in_progress&urgent=true&minProgress=50

Criterio técnico

Decisiones que vale la pena explicar

Una API común

Web y CLI consumen la misma API para no duplicar el CRUD ni las reglas de negocio.

Identidad desde el JWT

El userId de operaciones protegidas se obtiene desde req.auth.sub y no desde un body controlado por el cliente.

Password hashing

Las contraseñas se verifican con bcrypt y no se almacenan como texto plano.

Uploads controlados

Los archivos se validan y reciben nombres generados para reducir colisiones y evitar confiar en el nombre original.

Desafío

SSR y estado de autenticación

Handlebars se renderiza en servidor, mientras el JWT del cliente Web se guarda en localStorage. Por eso el template no puede leer directamente ese estado del navegador durante res.render().

Aprendizaje

Separar UX de seguridad

JavaScript cliente actualiza la navegación según el estado local, mientras que la seguridad real permanece en la API mediante express-jwt. Ocultar un enlace no sustituye proteger un endpoint.
